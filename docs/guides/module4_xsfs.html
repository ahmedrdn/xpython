Module 4 · xsfs: the secure file system

xPython framework guide, concept edition · goal → functions → data flow → connections → testing · 31 October 2026

In one line: xsfs is a folder where every file is automatically encrypted and sealed when written, and checked and decrypted when read. You use the normal open(), read() and write(); the crypto is invisible.

1. Goal

The ESP32's flash is a separate chip that anyone can read with esptool or a probe. Files saved normally (Wi-Fi password, settings, app data) are stored as plain text. xsfs protects them, so that:

  • nobody can read them from the flash (they're encrypted);
  • nobody can change them unnoticed (any change breaks the seal);
  • nobody can swap one file for another (each seal is tied to its file's name).

Analogy: a safe-deposit box with a clear window. People can see that there are boxes and what's written on their labels (file names), but not what's inside. If anyone forces a box, or moves the contents into another box, the bank notices at once.

2. How it works: a mount

xsfs plugs into MicroPython's file system as a mount: a folder that looks normal but is served by xsfs.

import xsfs
xsfs.mount("/secure", key="sfs", root="/.xsfs")
ArgumentMeaning
"/secure"The mount point: the folder you and your code use
key="sfs"The xkeys label of the AES-256 key. Created automatically if it doesn't exist
root="/.xsfs"Where the sealed files really live on flash

After that, open("/secure/config.txt", "w") works like any file, but what reaches the flash is /.xsfs/config.txt, sealed.

The sealed file format

[ "XSF1" 4 B | IV 12 B | tag 16 B | ciphertext (same length as your data) ]

A sealed file is always your data + 32 bytes. os.stat() through the mount reports the real (plaintext) size.

3. Main functions

You mostly use normal Python file functions inside the mount: xsfs implements them.

What you callWhat xsfs does
xsfs.mount(point, key, root)Creates the key if needed, creates the root folder, mounts. Returns the file system object
open(path, "r") + read()Loads the sealed file, checks the seal, decrypts → your data, or OSError EIO
open(path, "w") + write() + close()Collects the data; on close, seals with a fresh random IV and saves
"a" (append) modeOpens, adds, re-seals the whole file
os.listdir, os.stat, os.mkdir, os.removePassed to the real folder (names visible, sizes adjusted)
os.rename(old, new)Decrypts and re-seals under the new name (the name is part of the seal)
os.umount(point)Removes the mount; sealed files stay on flash

4. Data flow

What each protection stops

ProtectionStops
AES-GCM encryptionReading the file from the flash
The 16-byte tag (seal)Changing even one bit
The file name as AADCopying one valid sealed file over another
A fresh IV at every saveRecognizing "the same content as before" from the bytes
Temp file + renameA corrupted file after a power cut while saving
The key kept by xkeysCode that reads the key and decrypts elsewhere

5. Who uses xsfs

UserMount pointKey labelReal folderStores
xnet/xsysxsys/.xsysWi-Fi password, broker address, CA, TLS key + certificate
xloader/data (while an app runs)a_<hash>, one per app/apps/.data/<app>Each app's private data, sealed with its own key
you / system codee.g. /securesfs (default)/.xsfs (default)Anything you want protected

xsfs uses xkeys (encrypt / decrypt by label) and xcrypto (random IVs). Because every app has its own key and folder, one app can't read another's /data, even by copying the files: they'd open with the wrong key, giving EIO.

6. Test it yourself

These steps use their own test key and folders and clean up at the end. Use the paths for where you run them:

Name in the stepsPC buildBoard A
M (mount point)"/tmp/xs/secure""/secure_test"
R (sealed folder)"/tmp/xs/.sealed""/.sealed_test"

On the PC, first run import os; os.mkdir("/tmp/xs") once.

Step 1 · Mount

import os, xsfs, xkeys
M, R = "/tmp/xs/secure", "/tmp/xs/.sealed"      # or the board paths
xsfs.mount(M, key="test_sfs", root=R)
"test_sfs" in xkeys.list()                      # True: the key was created for you

Step 2 · Use it like a normal folder

with open(M + "/config.txt", "w") as f:
    f.write("wifi_password=Sup3r")
open(M + "/config.txt").read()                  # 'wifi_password=Sup3r'
os.listdir(M), os.listdir(R)                    # (['config.txt'], ['config.txt'])

Step 3 · Look at what is really on the flash

raw = open(R + "/config.txt", "rb").read()
raw[:4]                                         # b'XSF1'
b"Sup3r" in raw                                 # False: the password isn't there
os.stat(M + "/config.txt")[6], os.stat(R + "/config.txt")[6]   # (19, 51): + 32 bytes

Step 4 · Attack: change one bit

b = bytearray(raw); b[-1] ^= 1
open(R + "/config.txt", "wb").write(b)
open(M + "/config.txt").read()                  # OSError: [Errno 5] EIO

Step 5 · Attack: swap two files

with open(M + "/a.txt", "w") as f: f.write("role=user")
with open(M + "/b.txt", "w") as f: f.write("role=admin")
open(R + "/a.txt", "wb").write(open(R + "/b.txt", "rb").read())   # copy b's seal onto a
open(M + "/a.txt").read()                       # OSError EIO: the seal belongs to "/b.txt"

Step 6 · Rename is safe; big files are refused

os.rename(M + "/b.txt", M + "/c.txt")
open(M + "/c.txt").read()                       # 'role=admin': re-sealed under the new name
with open(M + "/big.bin", "wb") as f:
    f.write(bytes(17000))                       # OSError: [Errno 12] ENOMEM (limit 16 KB)

Step 7 · Attack: put back an OLD copy (this one is NOT detected)

with open(M + "/limit.txt", "w") as f: f.write("max_temp=50")
old = open(R + "/limit.txt", "rb").read()       # attacker keeps a copy
with open(M + "/limit.txt", "w") as f: f.write("max_temp=40")   # you update it
open(R + "/limit.txt", "wb").write(old)         # attacker puts the old copy back
open(M + "/limit.txt").read()                   # 'max_temp=50': accepted!

The old copy has a genuine seal for the same name, so xsfs can't tell it's old. See §7.

Step 8 · The wrong key can't open anything

os.umount(M)
xsfs.mount(M, key="other_key", root=R)
open(M + "/c.txt").read()                       # OSError EIO

Step 9 · Clean up

os.umount(M)
for n in os.listdir(R): os.remove(R + "/" + n)
os.rmdir(R)
xkeys.delete("test_sfs"); xkeys.delete("other_key")
Verified: these steps were run on the PC build of your firmware; every result matched what is written above, including Step 7's rollback being accepted.

Summary

GoalFiles that can't be read, changed or swapped, with the normal file API
MechanismA mount; each file = magic + random IV + tag + AES-GCM ciphertext, with the file name as AAD
Functionsmount() + normal open / read / write / rename / listdir / remove
Data flowWrite → fresh IV → xkeys.encrypt → .tmp → rename. Read → xkeys.decrypt → data or EIO
Used byxnet (/xsys), xloader (each app's /data), your own code
Doesn't stopRollback to an old copy, deletion, seeing names and sizes, a flash dump of the keys
